## 1.0.5 — 2026-10-10

- iOS map viewer: Directions is a menu anchored above the button (the action sheet floated at the top on iOS 26); TMAP added (Korean only, with Kakao Map / Naver Map); cancelling the system "Open in …?" prompt no longer falls through to the web map (which opened the app anyway). Uses `canOpenURL` when the host declares `comgooglemaps`, `kakaomap`, `nmap`, `tmap` in `LSApplicationQueriesSchemes`.
- Map viewer open (iOS + Android): the thumbnail grows opaque to full screen and is removed only after the map has rendered (max 1.2 s wait) — no blank-map flash or double image. Background fade is white in light mode, black in dark mode. iOS open 0.24 s / close 0.22 s (was 0.32 / 0.30).
- Android map viewer opens a little slower: image grow 360 → 420 ms, fade-in without an image 220 → 260 ms (close unchanged).
- Android map viewer: no flash on the first frame when opening. The open start state (transparent background, map panel off-screen, bubble image at the bubble rect — or, without an image, map transparent at 0.96×) is now applied before the first frame is drawn: set up in `onCreateView` and placed/started in the first `OnPreDrawListener` instead of `outer.post` (which drew one frame with the full map and an opaque black background first). The dialog window animation is also turned off in code (`setWindowAnimations(0)`, same as the theme's `windowAnimationStyle @null`).
- Map viewer from a `renderLocationThumbnail` bubble: the marker no longer changes size when the image grows/shrinks. The thumbnail is drawn at bubble width, so its baked-in marker (19% of the image width) was ~2.4× too big once the image filled the screen and then jumped to the real map-marker size. The renderer now also saves the same map without the marker (`<key>.base.webp`, cache key bumped → thumbnails re-render once); when `sourceImageUri` is such a thumbnail, the viewer uses the markerless image and draws the marker separately, tip on the point, going smoothly from the bubble's marker size to the live map-marker size (reverse on close) while the live map marker stays hidden. Other images (e.g. sent snapshots) behave as before.
- **`reverseGeocode` (new)**: `AttachmentKit.reverseGeocode({ latitude, longitude, languageCode? }): Promise<{ address, shortAddress, cached }>` and `clearReverseGeocodeCache()`. Uses the device geocoder (iOS `CLGeocoder.reverseGeocodeLocation(preferredLocale:)`, Android `Geocoder(context, Locale.forLanguageTag(lang))` with the async listener on API 33+) — free, no key. `languageCode` is passed as the locale as is (default: `setDefaults`/`init` languageCode as given, not reduced to the UI languages). Address format = Location tab (`fullAddress` / `shortAddress`; Android: address line without country name and postal code). Disk cache (iOS `Library/Caches/RNAttachmentKit/Geocode/`, Android `cacheDir/RNAttachmentKitGeocode/`), key `round(lat,5)|round(lng,5)|languageCode`, "no result" (`address: null`) cached too, 1000 max → trimmed to 800 least recently used, not part of the 24-hour temp cleanup. Same-key requests merged; geocoder called one at a time; 8 s timeout per call. Rejects (never cached): `E_INVALID_COORDINATE`, `E_GEOCODE_UNAVAILABLE`, `E_GEOCODE_THROTTLED` (iOS `kCLErrorNetwork` + GEO throttle → queued requests rejected and new ones rejected until `timeUntilReset`; Android `IOException` while online), `E_GEOCODE_TIMEOUT`, `E_GEOCODE_NETWORK` (offline), `E_GEOCODE_FAILED`. Logs contain only a key hash. Android library manifest adds `ACCESS_NETWORK_STATE` (normal permission) to tell "offline" from "no result". See `docs/location-api.md`.
- Map viewer: a missing `address` is filled through the same geocode cache and language (`addressLanguageCode`, sent by JS = `languageCode` as given or the `setDefaults` value). Android Location tab addresses now drop the country name (same formatter).
- Map viewer sticky open/close works when `sourceRect` and `sourceImageUri` have different aspects (e.g. 4:3 bubble cell + screen-ratio thumbnail shown with `resizeMode="cover"`): the image is always drawn center-cropped (cover) inside the animated cell, so the first frame equals the bubble and the cropped top/bottom unfold to full screen (reverse on close). Android: new `CoverImageView` draws the bitmap into the animated rounded rect (BitmapShader, no per-frame layout — the old `ImageView` resized via layout params lagged a frame behind its position).
- `renderLocationThumbnail`: `maxWidth` / `maxHeight` documented on `LocationThumbnailOptions`; when only one is given the other is no longer capped at 512 (both omitted → 512 × 512 as before). `width: 170, aspect: 'device', maxWidth: 512, maxHeight: 1152` → about 510×1105 px on a 3× device.
- **Location thumbnails rendered on the receiving device**: `AttachmentKit.renderLocationThumbnail(options): Promise<{ uri, path, width, height, cached }>` draws a chat-bubble map thumbnail from location info only, in the device's own theme, and caches it on disk (iOS `Library/Caches/RNAttachmentKit/LocationThumbs`, Android `cacheDir/RNAttachmentKitLocationThumbs`; 300 files max, trimmed to 250 by last use; not touched by the 24 h temp cleanup). Same look as the sent snapshot: teardrop marker with the `markerType` / `placeCategory` icon at the sent point and, when `myLatitude`/`myLongitude` are given (sender had "Share my location" on), the blue my-location dot with the span widened so both fit. Options: `latitude`, `longitude`, `width`, `height` or `aspect` (`'square'` 1:1 / `'portrait'` 9:19.5 / `'device'` this screen's ratio), `markerType?`, `placeCategory?`, `spanMeters?` (default 400 m), `myLatitude?`, `myLongitude?`, `themeColor?`, `appearance?`. Identical concurrent requests render once; iOS renders up to 2 at a time (`MKMapSnapshotter`), Android 1 at a time on a reusable off-screen `MapView`. Rejects `E_THUMBNAIL_FAILED` (e.g. offline, 10 s timeout) / `E_INVALID_ARGS`. `AttachmentKit.clearLocationThumbnailCache()`.
- `openGallery({ captureLocationImage: false })`: the Location tab sends immediately without taking a map snapshot (no `imageUri/imagePath/imageWidth/imageHeight` in `AttachLocationResult`); `imageSpanMeters`, `markerType`, `placeCategory`, `includesMyLocation` and `currentLatitude/Longitude` are still returned so the receiver can render the same thumbnail. Default `true` (unchanged behavior).

## 1.0.4 — 2026-10-10

Image source: iOS memory/disk viewer cache → download; Android `file://` as is, `https://` via the Glide cache. New native methods `openMapViewer` / `updateMapViewerSourceRect` (iOS + Android newarch/oldarch, TurboModule spec).
- Android map viewer follows `appearance` (light / dark / system) — `MapViewerDialogFragment.show(..., appearance)`.

- New native map viewer (Android `MapViewerDialogFragment.show(activity, lat, lng, title, address, markerType, themeColor, languageCode)`, iOS `MapViewerViewController(latitude:longitude:title:address:markerType:placeCategory:accentColor:languageCode:)`): full-screen map of a shared location with the same teardrop marker as the sender, ✕ close, glass button box (map type / my location — fits both me and the place), bottom glass card with title and "distance · address" (address reverse-geocoded locally if missing) and a **Directions** button (Android: `geo:` chooser of installed map apps; iOS: Apple Maps / Google Maps / Kakao Map / Naver Map, falling back to the web). Android is a DialogFragment (no new Activity → no AppState change). Dark map style on Android dark mode. New strings `location_directions`, `map_app_apple/google/kakao/naver`. Test apps open it when the location result image is tapped.
  - Sticky open/close from the tapped thumbnail: iOS `sourceRect` / `sourceImage` / `sourceCornerRadius` / `sourceRectProvider` (present with `animated: false`) — the whole viewer is revealed through a rounded mask growing from the thumbnail while the thumbnail image scales up and cross-fades into the live map, and shrinks back on close.   - Directions button is optional: `showsDirections` (iOS) / `showDirections` (Android), default on. Kakao Map and Naver Map are offered only when `languageCode` is Korean (iOS sheet: Apple Maps + Google Maps otherwise; Android uses the system app chooser).
- Location result gains `markerType` (`"current"` / `"pin"` / `"place"`) and on iOS `placeCategory`, so the viewer draws the same icon the sender saw (current = arrow, pin = location icon, place = category icon on iOS / location icon on Android). Android marker drawing moved to a shared `LocationMarker`.
